## 1. Ground-Truth Scenarios in `sample_capture.pcap`

- **Protocol:** UDP / DNS
- **Payload:** Query for `google.com` (Type A, Class IN).
- **Frames:** Frame 1.
- **Expected Outcome:** Classified as standard DNS; no security alert triggered.

### Flow 2: Legitimate HTTP Web Browsing
- **Client:** `192.168.1.100:49152`
- **Server:** `93.184.216.34:80` (example.com)

- **Sequence:**
  1. Client SYN (`0x0002`, Seq=100) -> Frame 2
  2. Server SYN-ACK (`0x0012`, Seq=500, Ack=101) -> Frame 3
  3. Client ACK (`0x0010`, Seq=101, Ack=501) -> Frame 4
- **Expected Outcome:** Full 3-way handshake established; zero alerts.

### Flow 3: External Host Reconnaissance / SYN Port Scanning
- **Attacker IP:** `10.0.0.99`
- **Victim IP:** `192.168.1.50`
- **Protocol:** TCP
- **Targeted Ports (15 distinct):**
  `21 (FTP), 22 (SSH), 23 (Telnet), 25 (SMTP), 53 (DNS), 80 (HTTP), 110 (POP3), 135 (RPC), 139 (NetBIOS), 443 (HTTPS), 445 (SMB), 1433 (MSSQL), 3306 (MySQL), 3389 (RDP), 8080 (HTTP-Alt)`
- **Frames:** Frames 5 through 19.
- **Expected Outcome:**
  - **Rule `PS-SCAN-001` Triggered (High Severity):** Attacker contacted 15 distinct ports (Threshold: $\ge 10$). Evidence displays exact list of probed ports and sample frame numbers `[5, 6, 7, 8, 9]`.
  - **Rule `PS-PROTO-005` Triggered (Low Severity):** Detected attempts to contact legacy cleartext ports (FTP-21, Telnet-23).

### Flow 4: Lateral Movement / Repeated SMB Brute Force / SYN Flood
- **Attacker IP:** `10.0.0.77`
- **Target IP:** `192.168.1.50:445` (Microsoft-DS / SMB)
- **Protocol:** TCP
- **Behavior:** 12 rapid TCP SYN connection attempts without completing handshakes (0 SYN-ACK responses received).
- **Frames:** Frames 20 through 31.
- **Expected Outcome:**
  - **Rule `PS-CONN-002` Triggered (Medium Severity):** 12 unacknowledged SYNs to port 445 (Threshold: $\ge 8$). Evidence reveals 0 handshake completions, pointing to authentication brute-force or filtered port knocking.
